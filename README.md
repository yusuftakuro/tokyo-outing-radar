# 東京お出かけレーダー（試験版）

「東京で今日何が起きているか」を少数紹介し、「行き先をひとつ出す」で代表駅・エリアを1件提案するスマホ向け静的Webサイト。

## 状態

- 確認済みのイベント：2026-10-12、17〜18日開催分13件（公式・行政情報から手作業登録）
- 登録イベントを日付・時刻・予算・予約要否で絞り込み
- 代表駅20駅からの地理的な近さで推薦順位を調整（**所要時間ではない**）
- 1件ずつ表示、「別の街を見る」は同じセッション内で同じエリアを出さない
- 常設の散歩候補は紹介後原則30日間非表示（新規候補が尽きた場合のみ再表示）
- イベントの日付が過ぎたら今日開催として表示しない。7日以内の予定は別枠で予告
- ログインなし。設定と直近表示履歴は端末内の localStorage のみ

**重要な制限**：イベント情報の自動取得・天気予報・公共交通機関所要時間の計算・現地開催可否のリアルタイム確認は未実装。現時点では毎日のイベントデータの手動更新が必要。登録された13件以外の網羅性は保証されない。

## 起動

ローカルで `python3 -m http.server 8000` を実行し、`http://localhost:8000/` を開いてください。静的ファイルだけなのでビルド不要です。

## GitHub Pages 公開

1. 新規リポジトリ `tokyo-outing-radar` を作成する（Public にすると無料の Pages を使いやすい。リポジトリの内容は公開されます）。
2. このフォルダのファイルをリポジトリのルートにアップロードする。
3. Settings > Pages > Build and deployment > Source: Deploy from a branch > Branch: `main` / `/(root)` > Save。
4. `https://<GitHubユーザー名>.github.io/tokyo-outing-radar/` を iPhone の Safari で開く。

プロジェクト名は仮称です。別名へ変更してもコード側のロゴ・説明文だけ差し替えられます。

## データを更新するには

- `data/events.js`: イベントの日時・料金・根拠URL・確認日・会場・説明。追加前に主催者または自治体で確認する。
- `data/areas.js`: 代表駅、エリア名、概略位置、常設の散歩先。イベントがなくてもここから提案できる。
- 同じ催しの重複登録を避ける。
- 予約必須イベントは推薦しない。予約制のサブプログラムは、自由観覧部分と明確に分ける。
- `verified` を更新した場合は、本当に公式サイトを再確認した日を入れる。
- データに間違いがあれば GitHub の以前のコミットへ戻す。

## 品質ゲート

`node tests/check-data.js` により日付形式・公式URL・会場紐付け・予約条件・重複ID等を検査。

`python3 tests/smoke_browser.py` は Playwright がインストールされている環境でブラウザの操作を検査します。
